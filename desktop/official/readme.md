# 默认桌面

界面材质、文字、圆角、阴影和动效规范见 [UI 设计](ui-design.md)。

## 触控

触屏按接触点映射成独立指针：一根手指对应一个 `pointerId`，各自产生 down/move/up，第一根手指 `isPrimary` 为 true。点按由输入聚合层合成 `click`，只在单指接触（没有出现两指以上）且主指针抬起时合成，多指手势留给交互层。

- DOM 模式（window）：浏览器为触摸生成的 pointer 事件和其他指针一样进入聚合层，`pointerId`/`isPrimary` 原样保留；`html`/`body` 设置 `touch-action: none`，关闭浏览器自己的平移、缩放与双击放大手势
- evdev 模式（desktop）：MT-B 用 `slot` + `ABS_MT_TRACKING_ID` 跟踪每根手指，绝对坐标按屏幕量程映射；没有 tracking id 的旧设备退回单指 `BTN_TOUCH` 路径
- 桌面光标只跟随主指针；落在客户端窗口上的每根手指都转发为 Wayland 触摸点（`input.touch` / `wl_touch`），落在桌面 UI 上的触摸仍走 pointer 事件供交互层实现长按、双指缩放等手势
- 桌面与 UI 只监听 pointer 事件，不依赖 mouse 事件

### 触摸板

desktop（evdev）模式下触摸板事件由仓库的 `src/utils/touchpad.ts` 封装成 `move`/`scroll`/`button`/`pinch`/`hold`/`multi*` 语义事件，桌面只订阅转换结果。绝对坐标只用于计算位移、手指数和捏合几何，不映射成光标位置。

- 单指轻触左键、双指轻触右键、三指轻触中键；轻触要求接触不超过 180ms、位移不超过 1.3mm（按设备分辨率折算，分辨率缺失时按 libinput 的 69×50mm 触摸板估算）；判定期间不移动光标，这段位移直接丢弃，确认是移动/拖拽后只发当前帧位移，避免开始移动时跳一下
- 单指移动光标；接触中移动超过 1.3mm 就按移动处理，不点击；按住超过 180ms 没有移动也不点击（libinput 的 hold 行为）
- 轻触在抬手时才按下左键，并等 180ms 拖拽窗口：窗口内第二下按住（移动超过阈值或保持到超时）沿用按住的左键进入拖拽，抬手结束拖拽；窗口内第二下快速抬起则按双击处理（先抬起上一次点击，再按下本次）
- 拖拽抬手立即抬起左键；没有第二下时拖拽窗口结束自动抬起，完成一次点击
- 两指先分类再发滚动：质心移动超过 1.5mm 且大于两指距离变化才判为滚动（内容跟随手指）；两指距离变化超过 8% 且不少于 2mm，或夹角变化超过 10° 判为捏合。分类期间的位移直接丢弃，判为滚动或捏合的那一帧只发本帧位移；一旦判为滚动，本轮接触不再改判捏合。捏合事件带 scale（相对 begin）和 rotation（相对上一次的顺时针角度）；捏合期间滚动继续，不互相取消
- 手指保持不动 300ms、质心位移不超过 2mm 发 hold；移动或换指取消。1-2 指的 hold 通过 `input.gesture` 转发给指针下的窗口，3 指及以上不转发（多指归桌面手势）
- 三指及以上移动单独发 `multiStart`/`multiMove`/`multiEnd`（swipe 语义）。三指是桌面手势：横轴与纵轴独立生效，横滑切换虚拟屏（预览里左右选窗口），纵向在搜索叠加、常规、全局预览之间连续移动；像全局快捷键一样消费，不发给应用。四指及以上作为 `swipe` 发给应用
- 本轮接触只要出现三指及以上，之后残留的两指/单指不再触发滚动、捏合、hold 或光标移动；避免三指滑动结束时没有同时抬手，剩下两指继续移动被误判成双指滚动
- 手指数允许变多：单指移动时落下第二根手指升级成双指滚动，两指再加第三指升级成多指手势。变少时本轮结束，残留手指不再触发低一级手势；例外是 2→1，剩下的单指继续移动光标
- window 模式下没有 evdev，宿主（KDE 等）把触摸板 pinch 合成成 `Ctrl+wheel`；桌面在物理 Ctrl 没按下时把它还原成 `input.gesture` 的 pinch（scale 按 `exp(-deltaY/100)` 累积），锁住目标窗口后转发；物理 Ctrl+wheel 仍按普通滚轮处理
- 同一轮接触里按过物理按键就不再合成轻触，物理按下会取代待判定的轻触或并入已按下的左键
- MT-B 设备用 `slot` + `ABS_MT_TRACKING_ID` 跟踪每根手指；没有 tracking id 的旧设备用 `BTN_TOOL_*` 手指数；完全没有接触信号的设备只保留光标移动
- 多指位移按全部活动接触点平均（不是只平均这一帧有位移的指），避免某一根手指偶尔没上报时质心突然偏移；单帧位移超过 20mm 或相邻帧位移突然增大按 libinput 的跳变检测丢弃，设备报有 fuzz 时按 fuzz 做坐标迟滞
- 双指滚动带方向锁：起手按累计方向向量锁定主方向，另一轴的轻微抖动不产生滚动；持续滑动或明确斜向移动后按 libinput 的规则放开两轴

## 虚拟桌面

一个虚拟屏可以放多个顶层窗口；空桌面始终存在，启动台固定在最右，空桌面在启动台左边。每个窗口有自己的舞台槽：槽铺满舞台，只应用所属虚拟屏的 `transform`、裁剪和缩放补偿；虚拟屏卡片只负责背景、空桌面、点击和拖放目标。常规状态和全局预览只驱动卡片和这些舞台槽，用 `AnimationGear` 补间，不再整体缩放外层容器。

- 普通模式：窗口在屏内自由移动、缩放；覆盖只看上层压住下层，按「交集 ÷ 下层面积」计算，默认阈值 80%，上层窗口自己不算被覆盖。
- 移动时，如果下层窗口会被压住超过阈值，先平移这些窗口让开（不改尺寸）；实在让不开才停在最后一个合法位置。
- 缩放时先改变窗口的层序，尽量找到没有覆盖冲突的位置；找不到零冲突层序才停在最后一个合法尺寸，松手后把被缩放的窗口移到新的虚拟屏。
- 点击窗口提升到该屏最上层并聚焦；如果提升后会压住上层窗口超过阈值，则不提升，形成隐式置顶。
- 移动、缩放、躲避和拖放落点都限制在窗口可用区内，不会顶进顶部工具栏。
- 全局预览：把一张卡片拖到另一张卡片，会把源屏最上层的窗口移到目标屏，落点按松手时的鼠标位置换算到目标屏；目标屏放不下时留在原屏。空桌面也可以作为目标，移入后补一张新的空桌面。
- 最大化把窗口按最底层处理：只看它是否被上层窗口盖住超过阈值。被盖住才移到新的虚拟屏；否则原地最大化，其它窗口留在它上面。
- 最大化/全屏前记住用户摆过的窗口位置，退出后回到原位置并固定住；没被摆过的窗口继续按恢复后的尺寸居中。从最大化进入的全屏沿用最大化前记下的位置。
- 全屏总是把窗口移到新的虚拟屏再全屏。进入全屏时工具栏立刻开始模糊淡出，不等窗口重排；全屏画面被总览、手势或切屏带偏时立即恢复，等停稳回到全屏屏后再隐藏。
- 不在聚焦虚拟屏上的窗口通过 `window.setFrameRate` 压到约 30Hz（server 按输出刷新率取最接近的整数因数）；聚焦虚拟屏上的窗口恢复跟随输出刷新率。切屏、移动窗口和开/关窗口时按差量下发。
- 空的应用屏自动回收；空桌面和启动台固定存在。

- 常规状态：当前屏在视口中央，左边是更旧的应用屏，右边是空桌面，空桌面右边是启动台
- 启动台：固定在最右，显示应用图标，点击图标启动应用；和空桌面一样是虚拟屏，也参与全局预览。新窗口仍然占用空桌面
- 顶部工具栏左侧有全局预览、搜索、启动台三个按钮，分别开关全局预览、开关搜索栏、切到启动台；全局预览按钮上滚轮或按住 `Super` 滚动都等同 `Super+←/→`，常规切屏、预览里移动聚焦面板。原生模式下鼠标一个滚轮事件切一屏，触摸板按三指手势的切屏距离和 `switchGestureGain` 设置累计；鼠标停顿或触摸板抬手会结束当前滚轮序列。滚轮序列的开始/结束、设备类型和鼠标格数挂在合成的 DOM `WheelEvent` 上，UI 可以直接监听 wheel 处理
- 切换后默认 3 秒内保持原来的空间顺序（缓冲），期间往左多滑几个屏还能直接往右滑回去；到点后只把当前停留的屏记为一次使用，再按最近使用顺序在内部重排（途经的屏不算），重排不做动画
- 三指手势是一个连续的二维状态：横轴选择虚拟屏，纵轴在搜索叠加（下）↔ 常规（0）↔ 全局预览（上）之间移动，两轴同时生效。纵轴可以穿过常规直接换段，一次手势从全局预览滑到搜索，或在搜索里上滑穿过常规进入预览，不需要先松手
- 纵轴 0 是常规：搜索栏收起；向下进入搜索叠加，搜索栏从工作区上方滑出；向上进入全局预览，搜索栏停在顶部。松手时按当前纵轴位置吸附到最近状态
- 手势的预览展开是分段接力：约 0.8 之前缩放和槽位间距按纵向进度线性变化，排布保持一整排围绕舞台中心横移，完全跟手；跨过 0.8 后不再绑定纵轴，用固定 200ms 动画把整排重排到 grid，避免不同手势速度造成观感差异。若中途拉回 0.8 以下，从当前视觉按上一帧剩余时间接着回线性；按钮/快捷键不跟手，直接朝停稳后的 grid 或常规布局走固定时长
- 横轴在常规/搜索里跟手切虚拟屏，一次可以跨过多个虚拟屏，松手按最近位置吸附；手指从左往右去左边的旧应用，从右往左去右边的空桌面；横滑倍率默认 4×。预览里横轴沿虚拟屏顺序连续移动同一个 `focus`（手指右移选左边的旧屏，和切屏一致）。松手后 `focus` 吸附到最近整数：常规里整排跟着 `focus` 移动；预览里 grid 卡片不动，只有聚焦面板和选中层级跟着 `focus` 移动。纵轴退回常规时 `focus` 保持连续，屏幕偏移只体现在窗口上
- 横轴的连续位置在常规和预览之间切换时保留：从常规带着已经滑过的半屏进入预览，再退回常规、重新上滑，画面仍停在同一个半屏位置，不会回到当前屏的正中
- `Super+←` / `Super+→` 沿当前顺序向右 / 向左切换（← 去右屏、→ 去左屏），`Super+D` 切到空桌面、再按一次回到最近使用的应用屏，`Super+Tab` 开关全局预览，`Esc` 或点击预览空白处退出
- 全局预览里 `Super+←/→` 同样移动聚焦面板；搜索框没有内容时普通 `←/→` 也移动聚焦面板，有内容时留给输入框。`Enter` 落到聚焦屏并退出预览；其它可打印键在搜索框没聚焦时先聚焦它再输入。`Super+Tab` 直接退出预览；搜索框有焦点时 `Esc` 第一次只失焦，第二次才退出
- 新窗口：当前在空桌面时直接占用它，并在右边补一个新的空桌面；当前在其他应用时，跳到最右的空桌面打开，视觉上从最右滑入
- 全局预览：所有虚拟屏（含空桌面和启动台）都铺进 grid，新的从右往左、再从上往下排列；行列数按屏幕宽高比估算，卡片保持虚拟屏比例；点击卡片切换过去，内容不接收指针；每个窗口右上角的关闭按钮在全局预览里保持固定视觉尺寸（不随卡片缩小），透明度跟预览进度绑定，手势中逐帧跟手；桌面自建内部窗口的关闭按钮按同一进度淡出，由卡片关闭按钮接管。三指横滑沿虚拟屏顺序连续移动焦点，聚焦面板在卡片之间跟手插值并立即聚焦对应窗口；常规插值基准跟着焦点连续横移，在 grid 完全展开后收敛到同一位置，退出预览会落到选中的窗口
- 聚焦面板位置由 `focus` 从同一份布局里连续插值：手势中跟手，松手吸附；按钮或 `Super+Tab` 进入/退出预览时跟着 `focus` 轴走。透明度由独立的 `AnimationGear` 驱动，只在进入/退出触发时启动一次，不跟移动进度，也不会被手势逐帧改写；出现与消失可互相打断，并从当前透明度继续。退出时面板一边淡出一边继续跟随焦点卡片移动。面板是纯白不透明圆角面板，不用 `backdrop-filter`

### 全局置顶

窗口可以进入全局置顶，多个置顶窗口共用一张置顶屏：

- 只有全局预览里能进入/退出：每个顶层窗口的关闭按钮左边多一个钉子按钮，透明度跟预览进度一致；已置顶时按钮反色
- 置顶屏固定在空桌面左边，不参与最近使用重排；第一次置顶时创建，最后一个置顶窗口离开或关闭后回收
- 加入置顶屏走普通多窗口屏的落位规则：尽量找不覆盖其它置顶窗口的位置，覆盖超过阈值且找不到空位时不加入（窗口留在原屏）
- 置顶屏内的窗口沿用普通屏的移动/缩放/提升/躲避和覆盖限制；拖动缩放导致覆盖超限时按普通逻辑换到新的应用屏，换屏后即取消置顶；置顶屏没有其它窗口时一起回收
- 进入第一张置顶屏时，新卡片从窗口当前所在卡片的视觉位置开始，再随 grid 重排滑到置顶区；之后加入的窗口直接落到置顶屏里的空闲位置。退出时把窗口换成一张新的应用屏，预览保持打开
- 常规模式下整张置顶屏固定覆盖在舞台坐标上，不随虚拟屏滑动，也不属于当前屏：切屏、搜索栏展开时都保持在同一位置，指针和滚动在所有虚拟屏都能命中；置顶窗口始终跟随输出刷新率
- 离开常规进入预览时，置顶屏上的所有窗口跟随聚焦面板一起缩放和移动；手势跨过 0.8 接力点（按钮/快捷键从进入起）后按置顶屏的 grid 动画过渡到它的卡片，退出预览时再跟随面板回到固定覆盖
- 置顶屏不接受其它窗口拖入，卡片本身也不能作为拖动源

### 屏视图状态

虚拟屏视图只存两个连续量，其余都是派生：

- `level`：纵轴。< 0 只影响启动器，≥ 0 是全局预览进度。屏布局永远只看 `max(0, level)`，所以搜索栏路径不会反过来影响屏。
- `focus`：横轴，绝对屏下标。整数表示停稳；小数表示手势/动画中的连续位置。当前屏是 `round(focusTarget)`，指针、键盘转发都用它，不用半动画中的视觉值。

键盘和按钮只改两个目标值，由 `AnimationGear` 驱动到离散目标；三指手势直接写当前值和目标，跟手。手势期间屏位置由 `(level, focus)` 的接力函数逐帧计算；非手势时屏直接朝停稳布局过渡。每屏的 `target`/`visual` 是渲染缓存，不参与状态判断。纵轴统一用 320ms 过渡，搜索栏和预览共用同一条时间线。

结构变化（新增/回收屏、重排）统一按锚点屏 id 重映射 `focus`；重排只在静止时发生且没有动画，所以下标重新对齐不会被看到。

搜索栏有两条连续路径，`level` 到位置不是单射，必须额外记路径：

- `line`：`n(-1) → h(0) → t(1)`，手势默认走这条；
- `direct`：`n(0) → t(1)`，只有按钮 / `Super+Tab` 从稳定 `n` 触发。

稳定态永远落在 `line` 的 `n/h/t` 上。直连只在运行中存在：从 `n` 切到直连时 `level` 做一次 `-1 → 0` 的换算，搜索栏视觉不动；走完在 `n` 或 `t` 结算时再折回 `line`。从 `t` 程序化退出时，直连进入的走 `t-n`，其余走 `t-h`，这个来源用 `tOrigin` 记住。

手势开始：

- 横轴以命令目标为基准。切屏动画没结束时起手，会先把 `focus` 对齐到目标，不把“当前屏”停在半路；
- 纵轴从当前视觉接管。正在跑的预览/搜索动画不会被跳到终点，手势沿当前路径继续；已经激活的直连被接管时保持直连，不会突然经过 `h`；
- 新手势永远走 `line`，即使上一次是直连进入的。

启动器只根据 `(level, route)` 画位置和透明度，不自己存路径。`applyAxes` 每帧都会调 `setLevel`，所以启动器只在“刚变成完全可见”时聚焦输入框；布局帧不能反复把焦点夺回来。

搜索栏完全可见时（常规搜索和全局预览都一样）桌面接管键盘：`window.blur` 全部客户端，core 会在 `leave` 前把按住的键补成 release。启动器完全收起、回到常规模式或解锁时，按 `focus` 轴选中的屏把焦点还给该屏记忆的窗口（每张屏记录自己最后聚焦的窗口；没有记忆或窗口已关闭就退回该屏最上层）；已有焦点（点击/启动流程刚选中窗口）时不抢。

### 子窗口

带父窗口的客户端窗口（`WindowInfo.parent`，来自 `xdg_toplevel.set_parent`）是子窗口，不占虚拟屏：

- 叠在父窗口所在屏的上面，初始居中覆盖父窗口；尺寸由客户端决定（桌面下发 `configure(0×0)`），所以对话框不会被 800×600 撑大
- 与父窗口一起拖动；用户拖动或缩放过后不再自动居中
- `modal`（`xdg-dialog-v1`）子窗口挡住父窗口的指针/滚动/键盘，点父窗口只会把焦点收回对话框并闪一下边框；访问其他虚拟屏不受影响
- 命中测试与滚动按「子窗口先」排序，同客户端的父窗口不会吃掉对话框的事件
- 总览里跟着父窗口那张卡片缩放，不单独成卡，也没有自己的关闭按钮
- 父窗口关闭时，挂在上面的内部窗口（文件选择器）一起关闭

### 启动器

顶部启动器输入框有三个位置：屏幕外隐藏、常规模式上三分之一、全局预览顶部。默认隐藏；常规模式下三指下拉或 `Alt+Space` 从工作区外部顶部滑出，停在约上三分之一处；`Alt+Space` 可收起展开的搜索栏。展开/收起过程跟手，松手按进度吸附；三指上滑会先经过常规收起搜索栏，不松手继续上滑就进入全局预览。输入内容后搜索应用、窗口和虚拟屏，`↑`/`↓` 选择、`Enter` 执行；执行结果、按 `Esc` 或点击搜索栏外部都会收起搜索栏。

全局预览时启动器固定在 grid 上方并始终显示，不能用手势或 `Alt+Space` 收起；grid 顶部会为它留出空间。手势和按钮的行为是分开的：

- 搜索栏有三个稳定状态：隐藏 `h`、常规 1/3 `n`、grid 顶部 `t`。手势的纵轴是一条 `n-h-t` 连续路径，`h` 对应 level 0；一次手势可以穿过 `h` 在 `n` 和 `t` 之间移动，不需要先松手，反向也可以
- `n-t` 直连只由按钮 / `Super+Tab` 从稳定 `n` 明确触发，此时搜索栏直接从 1/3 移到顶部，不隐藏。手势永远不会自己创建这条直连，即使记得上次是从 `n` 进来的，新手势仍然走 `t-h-n`
- 手势开始如果已有路径在跑，就锁定当前路径：`n-h-t` 线上的过渡绑定到 level 继续走；按钮触发的 `n-t` 直连被三指接管时也绑定到 level（`n=-1`、`t=+1`），保持在直连上不走 `h`，这是唯一例外
- 横轴始终独立生效：常规/搜索里切虚拟屏，进入预览后改为左右选窗口，不会因为同时在上下滑而被忽略
- 按钮 / `Super+Tab` 切换常规与全局：搜索栏可见时在 1/3 和顶部之间移动，隐藏时从外部进入顶部
- 程序化退出预览（按钮、`Super+Tab`、`Esc`）：`n-t` 直连进入的 `t` 走 `t-n` 直连，其余走 `t-h`；手势退出则按最终纵轴位置落到最近状态

#### 搜索

搜索栏先在本地做模糊匹配，再按处理器并发补齐结果；应用、窗口和虚拟屏按匹配得分混排，同分再按处理器顺序。输入只支持拉丁字符；应用名会把 `nameLocal` 里的中文经 `src/latin.ts`（`pinyin-pro`）转成拼音，全拼（`huohu`）、带空格的拼音（`huo hu`）和首字母（`hhllq`）都能命中，原始拉丁 `name` 也同时参与匹配。

- 处理器：应用（启动 `exec`）、窗口（跳到对应虚拟屏并聚焦窗口，含设置/文件选择器等桌面内部窗口）、虚拟屏（空桌面、启动台和应用屏都可以切过去）
- 异步：每次输入递增序号并 abort 上一次搜索；处理器返回时如果输入已变化就丢弃；跨处理器按每条结果的得分统一排序。应用列表由 `MSysApi.getDesktopEntries` 缓存，结果图标在行创建后再异步加载，过期回调不再写 DOM
- Copilot 键：Windows 键盘的 `Shift+Super+F23` 组合和只发 `F23` 的固件都能识别。搜索栏隐藏时打开并聚焦输入；已展开且有输入时把文字交给 AI；有输入但没有注册 AI 处理器时显示「AI 未接入」
- 接入：`SearchEngine.register(provider)` 增加处理器，`SearchProvider.search(query, signal)` 可以同步或异步返回结果；`launcher.setAiHandler(handler)` 注册 AI 处理器，不接 AI 时接口保留但不执行

### 应用启动动画

启动台、开始菜单、顶部快捷应用和搜索栏的应用结果都经过同一个启动入口。点击后在图标位置创建启动 frame（从第一帧就存在），窗口到达只把 content 填进去，元素不换。整个启动分三根轴，各自只写自己的属性：

- **屏幕轴**：`screen.visual`。按下阶段先不切屏，回弹后创建占位应用屏（或把已创建的窗口放进去）并跳过去
- **动画轴**：窗口在物理屏上的位置。默认固定视口坐标，虚拟屏在后面滑，窗口看起来不动；只有屏幕被其他操作接管（切屏按钮、手势、总览）时才改为跟随屏
- **渲染轴**：盒子的尺寸和内容。盒从图标本身的矩形（默认 64×64）长到窗口大小；内容用 `transform` 非等比拉伸铺满盒（GPU，不重排大 buffer），不裁切、不留空边，也不需要溢出处理。resize 有独立时钟，可以跨过启动收尾和预览

具体行为：

- 图标先缩小并淡出；完全透明时整帧（mask 在内）从同样的缩小状态淡入，mask 始终铺满 frame，顶栏和内容不会从 mask 边缘露出来
- 飞入只写盒的位置：中心从图标走到目标位置；盒的尺寸由独立的 resize 齿轮负责，从图标矩形非等比长到目标盒。`mask`（白色底 + 图标）铺满盒，图标由 DOM 居中，盒的比例变化不会影响图标。窗口内容用 `transform` 非等比拉伸铺满盒（基准 top 已经是标题栏高度），中间尺寸会变形，但没有空边也不需要裁切。飞行期间槽保持恒等，`slot.scale` 只可能来自屏幕轴
- 客户端首帧一到就替换 mask，不等支配：mask 淡出和盒 resize 同时开始、用同一段时长、同时结束。中间尺寸仍然是内容非等比拉伸，所以替换过程中不会留边或溢出
- 屏幕被接管时，把当前视口矩形换算成屏内坐标（切换瞬间视觉位置不变），之后槽跟随 `screen.visual`。飞行没结束就沿用剩余时间，已经结束就用固定追平时长（和屏幕过渡一致），手势中也有界
- 支配时机：固定坐标阶段是 max(屏幕停稳, 飞行结束)，因为飞行瞄的是**已提交**的屏位置，停稳那一刻两者重合，交接零跳变；被接管后是追平结束，不再等屏停稳
- 窗口创建时先用 `WindowInfo.rect × info.scale` 算显示尺寸，请求服务端装饰时再加标题栏高度；首帧呈现前窗口区域填白底，实际 surface 尺寸回来后更新外框
- 窗口到达时只填 content/handle 和标题栏；`mask` 是 frame 内部的层，窗口内容在它下面。首帧没出来时 mask 一直盖着，盒停在飞行/支配结束时的位置；首帧出来才替换，窗口内容在替换结束时正好铺满。frame 和盒从头到尾不换，也不搬进虚拟屏卡片
- resize 在支配时如果还没结束，转交给 frame 继续按自己的时钟走完。它不参与支配判定，也不影响启动收尾，可以一直跑进全局预览。首帧替换的 resize 和淡出共用时长，结束时刻一致
- frame 落到目标位置仍然是空（还没有窗口）时，右上角以透明+模糊淡入的方式露出关闭按钮，不必等超时；窗口晚到后照常接管同一个 frame。进程可能在图标阶段就退出（单实例交接、启动失败），这时不显示按钮，避免压住启动图标，等 frame 落地成全尺寸空槽再淡入
- 关闭按钮是两个固定 DOM：没有窗口时是 kill（结束进程树并回收占位屏），窗口出现后换成 close（发 `window.close`），收尾后交给标题栏；不按状态重新指派事件
- 新窗口在客户端给出几何之前用默认 800×600（乘输出缩放）占位；界面缩放重算不会把还没有几何的窗口缩成 1×1，多个这样的窗口也不会叠在正中
- 启动认领的窗口不在创建时抢焦点：等 mask 替换完（可能早于支配）并且窗口真正接管屏幕时再激活。Electron 类客户端会丢掉初始化完成前收到的激活，之后一直不出首帧
- 窗口关闭时先按外框当前视觉矩形把它移到不归属虚拟屏/面板的关闭层，再立即切屏；外框最后提交的内容保留到淡出结束，虚拟屏回收不会带走它

## 窗口缩放

窗口没有边框，四周铺一圈透明热区：四条边各 6px，四个角 14px，热区跨在窗口边界上、内外各占一半。按住热区拖动即可缩放，拖动上边/左边时窗口位置同步移动，最小尺寸 200×150（逻辑 px）。

- Wayland 客户端窗口在拖动中把新尺寸转成 surface 逻辑尺寸，每帧最多通过 `window.setSize` 下发一次，由客户端按自身约束重绘；客户端提交前的 `window.changed` 不覆盖桌面预览，抬手后短暂等待客户端几何，超时再以客户端实际尺寸为准
- 设置窗口这类桌面自己创建的 DOM 窗口只改 DOM 尺寸，不经过 Wayland
- 缩放中指针事件不转发给客户端；全局预览里隐藏热区，最大化窗口不能缩放
- 手动缩放后暂停该窗口的自动居中，与拖动窗口一致
- 手动拖拽缩放仍走客户端预览，不接自动过渡。其余自动 resize（最大化/恢复、全屏进出、界面缩放、客户端自己改尺寸）走整框过渡：frame 的位置和尺寸用同一段 180ms 动画，内容按盒非等比拉伸；开始前用窗口最近一帧截一张旧内容快照，快照随盒拉伸并淡出，新内容同时淡入。还没画过首帧的窗口没有快照，只做位置/尺寸过渡
- 内容淡化只作用于 surface 画布；`backdrop-filter` 的模糊层在整个过渡里保持常亮，模糊区域变化时直接切到新区域，不做双层交叉淡化
- 居中由桌面在已知的尺寸变化点自己计算，不监听窗口 DOM 尺寸。自动 resize 期间暂停居中，结束后再交还；没被用户摆过的窗口最终仍落在居中位置
- 最大化/全屏前记住用户摆过的窗口位置（拖动或缩放过的窗口）。退出后回到记忆位置并固定住，不再自动居中；恢复后的尺寸放不下时夹回可用区。没被摆过的窗口仍按恢复后的尺寸居中，收缩动画一路朝居中目标走，不会先贴住左上角再跳回来
- 悬停热区时光标变为对应方向的缩放形状（自定义光标已支持 `ew-resize` / `ns-resize` / 两个对角）

## 光标

自定义光标用「一个基座 body + 前后装饰层」组合，全部是 DOM，不使用 SVG。装饰层可以是横线、方框描边、圆角方块或白色加减线，过渡时旧层淡出、新层淡入。

已设计的形状：

- `default`：圆点
- `pointer`：圆角方形
- `text`：竖线；`vertical_text`：横线
- `context_menu`：较窄的中线为 body，上下各一条横线装饰
- `cell`：外框为 body（空心描边），横/竖两条装饰组成十字
- `crosshair`：横线 body + 竖线装饰组成十字
- `copy`：前面的圆角方形为 body，后面偏移的圆角方形为装饰
- `move`：菱形描边为 body，横/竖两条装饰组成十字
- `all_scroll` / `all_resize`：和 `move` 相同
- `grab`：16×16 无圆角方形；`grabbing`：10×10 小无圆角方形
- `no_drop` / `not_allowed`：小圆 body + 大斜线前景装饰
- `zoom_in` / `zoom_out`：外圆为 body，白色加/减为前景装饰
- `progress` / `wait`：静态米字装饰，body 是一个小圆点；`progress` 的圆点在左上，`wait` 的圆点在中间
- `help` / `dnd_ask`：三个水平圆点，中间圆点为 body，左右为装饰
- `alias`：左边圆点为 body，右边一个方形装饰

形状之间用 `AnimationGear` 补间 body 的几何参数（宽、高、圆角、旋转），所有形状对先共用同一套过渡（150ms easeOut），个别 pair 可以之后单独覆盖；装饰层独立淡入淡出。图片光标和隐藏在形状之间直接切换，不做补间。窗口缩放热区的 `localShape` 覆盖也走同一套过渡。

没单独设计的 resize 方向先复用现有横/竖/斜线几何：`e`/`w`/`col` 用横线，`n`/`s`/`row` 用竖线，`ne`/`sw` 用 `/`，`nw`/`se` 用 `\`。其余未提到的形状仍回落到默认圆点。

线 resize 之间保留内部方向语义：单向方向为 0/45/…/315，`ew`/`ns`/两个对角方向和 `col`/`row` 是双向线。过渡时按这个方向旋转：双向 ↔ 单向共线时不旋转，非共线才旋转；反向单向之间会转 180°。旋转只发生在过渡中，过渡结束立刻切回目标的无方向线条，静止帧本身不显示方向。

resize ↔ `move` / `all_scroll` / `all_resize` 过渡时优先用十字的一条臂作为 body：横/竖 resize 不旋转，直接作为对应的横/竖臂；斜 resize 统一用横臂作为 body 旋转成斜线（竖臂作为装饰），保证进入和退出用的是同一条臂、可逆。菱形外框和另一条臂作为装饰淡入/淡出。`move` 与其它非线 resize 形状的转换仍以菱形外框为 body。

`text` / `vertical_text` / `crosshair` 是一组独立的过渡：`vertical_text` 与 `crosshair` 共用横线 body，只淡入淡出竖装饰；`text` 与 `crosshair` 之间让竖线保持为 body，横线作为装饰淡入/淡出，不做旋转或尺寸伸缩。两条线的 body/装饰角色互换发生在过渡结束切回无方向帧时，视觉上连续。

每个设计可以带 `hotspot`，缺省为局部坐标原点（当前所有普通形状都在中心）。`progress` 的热点在左上小圆点 `(-8, -8)`，所以整个米字会偏移到指针右下；热点切换时视觉内容会随过渡一起平移。预览矩阵的 `normal` 行用红圈标出每个形状的热点。

`test/cursor/cursor_preview.ts` 把桌面自身的 `normal` 默认静态状态和全部形状按行、列铺成上三角矩阵（过渡来回播放，反方向共用同一格）。`normal` 行不参与动画；其余设计不同的单元格自动播放 `from ↔ to`，两端各停留约 1 秒，初相位错开避免整张矩阵同时闪烁。

## 锁屏

`Super+L` 从桌面进入锁屏。锁屏界面显示后点击或按 `Enter` 进入密码输入，校验通过后回到桌面；30 秒无操作自动息屏。在时钟界面按其它可打印键会直接进入密码界面并输入该字符。密码界面按 `Esc` 回到时钟界面，时钟界面按 `Esc` 息屏；息屏时任意输入只用于唤醒并回到锁屏界面，不交给应用。

密码界面底部有一个独立的 ASCII 屏幕键盘，直接写进密码框，不经过输入法，适合触屏设备。它和桌面内的虚拟键盘共用按键布局，但不带表情、Unicode 和触控板页。

合盖沿用同一套流程：未锁屏时先锁屏，锁屏界面已显示时直接息屏；开盖回到锁屏界面。

## 退出

`Super+Shift+E` 或 `Ctrl+Alt+Delete` 关闭桌面窗口，结束当前桌面进程。

## 设置

顶栏不放设置入口，设置作为模拟应用出现在开始菜单里。设置窗口是桌面自己创建的 DOM 窗口，不是 Wayland 客户端，但和客户端窗口共用同一套窗口逻辑：

- 占用一个虚拟桌面（`viewData.addWindowScreen`），打开时居中，参与全局预览
- 点击后聚焦，点击桌面或其他窗口时失焦，键盘事件留在 DOM 内处理
- 标题栏可拖动，关闭时回收虚拟桌面和居中管理
- 打开中的设置窗口再次点开始菜单里的设置会跳回它所在的虚拟桌面

设置项：
- 外观：`icon.theme` 应用图标主题、桌面绘制的窗口圆角、桌面壁纸和锁屏壁纸。壁纸分别用桌面自己的文件选择器选择本地图片（只列图片），默认居中填充；没有自定义时使用自带壁纸。设置里只保存图片路径（`wallpaper.desktop` / `wallpaper.lock`），启动和切换时用 `MSysApi.nativefs.readImage` 读取
- 显示：Wayland 客户端缩放 `desktop.scale`（100% / 125% / 150% / 175% / 200%）。缩放后 surface 逻辑坐标不变，
  客户端 buffer 与窗口 DOM 尺寸按比例放大，桌面自绘 UI（工具栏、启动台、设置窗口、输入法候选、光标和窗口 resize 热区）也跟随同一个缩放。winit 后端和普通窗口模式跟随宿主桌面，myde 内部固定 1x。
  下方帧时间图表按需启动，实时采样桌面界面的 `requestAnimationFrame` 帧间隔，并按当前输出刷新率画出预算线
- 触摸板：单指指针速度 `desktop.touchpadSpeed`（libinput 速度设置 -1 ~ 1）、自适应加速度 `desktop.touchpadAcceleration`、双指滚动速度 `desktop.touchpadScrollGain`、自然滚动 `desktop.naturalScroll`
- 手势：三指横滑切屏倍率 `desktop.switchGestureGain`（默认 4×）、切屏后重排延迟 `desktop.reorderDelay`（默认 3000ms）
- 输入法：候选窗预编辑 `ime.panelPreedit`（`auto` / `always` / `never`）
- 互联：启用开关、本机 ID、已配对设备列表和忘记设备；添加设备时显示本机配对 ID/PIN，输入对方配对 ID/PIN 和是否记住
- 窗口：新窗口居中，保存到 `desktop.centerWindows` 命名空间
- 关于：重启桌面，重新载入桌面界面（会关闭正在运行的窗口）；不会重启 myde 进程

顶栏有互联工具，类似 WiFi：开关互联、显示本机 ID、列出已记忆和当前连接的设备；点击设备可在连接/断开之间切换。互联开关状态保存在 `connect.enabled`。

`test/frametime` 用同一份 `src/frame_chart.ts` 做独立预览：`pnpm test:frametime` 启动 vite 后，在 myde 里用浏览器打开终端输出的地址；可切换窗口与刷新率、实测刷新率，并用持续负载或一次性长帧验证图表。

逐帧流畅度（动画是否分散到多帧、输入后是否立即响应、打断后是否立即反向）由 `test/smoothness.test.ts` 在私有 headless 显示里自动检查，运行 `pnpm test:smoothness`（先 `pnpm build:desktop`）。采样方式和指标见[测试 runner](../../src/test_runner/readme.md#流畅度测试逐帧像素)。

窗口打开动画单独由 `test/window_open.test.ts` 检查：真实 Rust Wayland 窗口按不同时刻建窗/提交首帧/切全屏，覆盖大 buffer、永不出首帧、窗口晚到和空面板提前取消，同时断言虚拟屏只增加一张。运行 `pnpm build:test-apps && pnpm test:window-open`（还需要先 `pnpm build:desktop`）。

## 文件选择器

监听 `MSysApi.portal` 的 `fileChooser.request`，用和设置窗口相同的内部 DOM 窗口呈现；一个窗口同时只显示一个请求，后续请求排队，关闭后自动显示下一个。

选择器挂在发起请求的应用上：`parent_window` 经 `server.windows.lookupExport` 解析成应用窗口（解析不到时退回当前聚焦窗口），作为内部窗口的父窗口覆盖在应用上；`modal` 请求会挡住应用直到选择器关闭。应用窗口关闭时选择器随之关闭，请求按 `req.cancel()` 收尾。

- 左侧位置栏来自 `portal.browse.places()`，portal 不可用时退回主目录扫描；主目录、桌面、文档、下载、音乐、图片、视频和根目录按是否存在显示
- 目录枚举用 `MSysApi.nativefs.list`，显示名称、大小和修改时间；目录项优先自然排序，符号链接标注“链接”
- 工具栏提供后退、上一级、刷新和面包屑；点击目录进入，双击文件按模式打开或填入保存文件名
- 打开文件支持 `multiple`：点击文件切换选中，再次点击取消，双击只打开当前文件；按过滤器筛选文件。保存支持单文件名和每行一个文件名的多文件模式；目录请求未选择子目录时返回当前目录
- portal 的 `filters` 显示为筛选下拉框，`choices` 渲染为下拉框或开关，`accept_label` 作为确认按钮文字
- `Esc` 取消，`Enter` 确认；窗口右上角关闭和系统 `Request.Close` 都走 `req.cancel()`

手动测试：

- UI 调试（浏览器 + mock 文件树）：`pnpm test:file-chooser`
- 真实 portal 弹窗：`cd test/electron_app && npm run file`，用窗口里的文件输入框或保存下载按钮触发；在 MyDE internal portal 环境里启动该应用即可看到官方桌面的选择器

UI 调试页在 `desktop/official/test/file_chooser`，直接复用真实的 `file_chooser.ts`，只替换 `nativefs.list` 和 `portal.browse.places` 的 mock 数据。

## 输入法

通过 `MSysApi.inputMethod` 连接 fcitx5，桌面作为输入上下文客户端处理按键，不实现 Wayland 的 input-method 协议。

- 只拦截实现了 text-input 的聚焦窗口；没有 text-input 的客户端按键原样转发，输入法不生效
- 预编辑和上屏走 `input.text`，候选窗是桌面覆盖层，优先贴 text-input 光标矩形，缺失时贴鼠标；虚拟键盘打开时候选改到键盘里的候选栏显示
- 顶栏输入法工具显示 中/英/关，点击后在列表里直接切换输入法；`keyboard-us` 作为关闭输入法项，选中后按键直接转发给客户端
- 默认快捷键：`Ctrl+Space` 激活/停用合成，`Super+Space` / `Super+Shift+Space` 切换输入法
- 配置在 `settings.json` 的 `ime` 命名空间：`toggle`、`nextIM`、`prevIM`、`panelPreedit`
  - `panelPreedit`：`auto`（默认，fcitx 已在发内联预编辑时候选窗不重复显示）/ `always` / `never`
- 候选窗和托盘弹窗的视觉分别在 `src/ui.ts` 的 `imeCandidatePopup` / `imeTrayPanel`，静态预览见 `test/ui_example/ui_demo.ts`

## 虚拟键盘

顶栏的键盘按钮（输入法工具旁）打开/关闭桌面内虚拟键盘；面板可拖动（标题栏左侧握把）、右下角缩放，位置和大小保存在 `settings.json` 的 `keyboard` 命名空间。

- 标题栏标签分为极简键盘、常规键盘、触控板、表情和 Unicode；键盘标签只显示键帽，常规配列、触控板键盘位置、粘滞键说明和输入法切换收在齿轮打开的“键盘设置”页里
- 极简是手机键盘，带数字/符号层；常规是物理键盘，可在设置页切换 68 / 75 / 87 / 98 / 104 配列；68 没有独立 F 行和导航区，用 Fn 取 F1-F12 和 Home / End / PgUp / PgDn
- 键盘页是美式 ASCII 布局；极简布局的“123 / #+= / ABC”在层之间切换
- 修饰键默认开启粘滞键：Shift / Fn 单击一次性、再单击锁定、第三次取消；Ctrl / Alt / Meta 是粘滞开关键，一次按键后自动释放。设置页里的指示点和修饰键高亮显示当前状态
- 触控板页顶部有一个“不显示键盘 / 极简 / 常规”开关；选了键盘后，触控板面板和键盘同时显示，触控板在上 / 下 / 左 / 右由设置页决定
- 输入法切换器在设置页里，列出当前组的输入法并直接切换；和工具栏的输入法工具是同一个状态
- 合成中的预编辑和候选直接来自输入法 API，显示在键帽上方的候选栏里：左侧合成文本，中间候选词（点击上屏），两侧翻页。候选栏高度固定，有没有候选键帽位置都不变；键盘打开时浮动候选窗不再弹出，关掉键盘后恢复
- 英文输入经过 `ImeController`：能用输入法时按键先送给 fcitx5，合成结果按输入法正常通道上屏；没有 text-input 或输入法停用时按键原样转发。DOM 输入框（启动器搜索、设置、文件选择器等）改用 `inputSim` 合成按键，直接写入当前焦点
- 表情页按分类列出常用 emoji，Unicode 页提供十六进制码位输入和常用字符分组；插入时优先走 `input.text`，客户端不支持 text-input 时只有可打印 ASCII 会退回按键
- 触控板页由触控面板、左/中/右键和右侧一个可滚动的条形区域组成；单指移动指针、轻触左键，双指轻触右键、双指滚动和捏合，三指轻触中键、三指滑动走桌面切屏/预览手势，四指滑动作为 swipe 发给应用，和物理触摸板一致；滚动方向和速度沿用 `desktop.naturalScroll` / `desktop.touchpadScrollGain`，指针速度和加速度设置只作用于物理触摸板
- 锁屏密码行左侧有独立的键盘开关按钮，因为工具栏在锁屏不显示；它显示/隐藏锁屏的 ASCII 键盘
- 锁屏密码界面仍然使用独立的 ASCII 键盘，直接写进密码框；静态预览页同时展示常规键盘和这个密码键盘
- 静态预览：`npx vite desktop/official/test/virtual_keyboard`

## 剪贴板

数据层在 `src/clipboard.ts`，UI 在 `src/clipboard_tool.ts`，是顶栏一个和 WiFi 同类的工具：

- 点击图标打开历史；拖拽来源的条目带「拖拽」标记，点击任意条目把它放回剪贴板
- 客户端开始拖拽时自动展开弹窗并高亮列表，松手把拖拽内容收进「拖拽」分组
- 弹窗宽高固定，内容多少不改变布局；底部一行分别清空拖拽和剪贴板历史
- 按住条目拖出：桌面作为 DnD 源，松手落在应用窗口上就投递过去
- 遵循「server 只发事件、桌面持有字节」：
  - 客户端复制 → `clipboard.changed` → 桌面按 mime 立刻 `clipboard.read` 取进历史；密码管理器标记的 mime 跳过
  - 源客户端退出/销毁 source → `sourceGone` → 把最后一条 `clipboard.set` 回去，内容不随应用消失
  - 应用粘贴桌面历史 → 桌面只声明 `{ id, mimes }`；server 在 `receive` 时用 `clipboard.requestData` 回来要字节
  - 历史上限：50 条 / 单条 32MB / 总量 128MB；文本预览截断到 2000 字符

## 工具栏弹窗

弹窗展开、收起用锚点缩放：缩放原点沿弹窗靠锚点的那条边，另一轴对准实际按钮中心；靠边的弹窗被浏览器平移后也不会从弹窗自己的中心弹出。关闭时先把画面锁在当前坐标，再开始收缩，之后锚点元素被移除（例如托盘项退出）也不会跳到别的锚点。

每个工具弹窗的第一个 L2 会跟着状态显示氛围动效，动效只在 L2 内部、内容下层绘制；状态关闭后隐藏，弹窗收起时动画随之停止。动画由 `AnimationGear` 驱动：Wi-Fi / 蓝牙 / 互联在弹窗展开时从中心用圆形遮罩向外扩开并启动自身循环，收起时循环保持运动，遮罩反向收完后暂停；同时该 L2 的底色在半透明白和 L3 实心白之间用同一组时长过渡。

Wi-Fi / 蓝牙的下拉里，设备列表行点击在连接/断开之间切换，已连接的行右侧显示“已连接”；列表只含已保存的 Wi-Fi 网络和已配对的蓝牙设备，不做密码输入和配对界面。

电源下拉的第一条 L2 显示主电池；没有电池（如台式机）时整条隐藏。下面的设备电池列表不重复这台电池，也不显示类型或型号未知的设备。

- 时钟：点击顶栏时间展开，大号显示时、分、秒，并显示完整日期、星期和本地时区（UTC 偏移）

## 底部应用栏

运行中的应用在底部应用栏显示图标，指针停留时弹出该应用的窗口预览。每张预览卡片固定 200×150：标题单行省略，窗口截图按比例放进固定缩略图区，不同窗口比例不会改变卡片大小；同一应用有多个窗口时按栏方向横排或竖排。切换图标时旧预览淡出、新预览淡入，弹窗尺寸和锚点位置一起用 `AnimationGear` 和锚点替身的过渡平滑移动，不会瞬移或跳变。窗口还没画出首帧时显示“暂无预览”。

- Wi-Fi 开启：底部中间向上的绿色同心细线水波
- 蓝牙开启：左边中间向右的蓝色水波
- 互联开启：中心圆点，以及几个不同速度、交替方向的紫色圆点环绕
- 电源：整行作为电池进度条。静音、平衡、性能都是 L3 实心白底细条纹，线色分别为黄、绿、蓝；平衡且低于 20% 时线色变红。充电为绿底白条纹，未充满的一段有绿色条纹向左流动。所有条纹都向左走，速度依次为充电流入线最快、性能次之、平衡再次、静音最慢；充电时电量条上的消耗条纹仍按当前模式的速度。填充区的消耗条纹集中在电量分界线附近，向左渐隐；分界线处始终有一条固定彩色细线。电量变化时分界线、填充宽度和右侧充电线一起过渡；充电切换时底色、条纹色和分界线色平滑变色，右侧充电线淡入淡出；消耗条纹锚定在分界线上，性能模式切换时速度平滑过渡。

## 工具栏临时提示

工具栏工具除下拉弹窗外，还能弹一个自动消失的临时提示（OSD）。提示和下拉弹窗共用玻璃材质、锚点定位和缩放淡入动画，二者互斥：下拉展开时不显示提示，打开下拉会把正在显示的提示立即收起。

提示共用一个纵向滚动列表，列表本身是唯一的 L1，负责毛玻璃、padding 和项间距；每个 OSD 是这个列表里宽度、高度一致的条目。列表按内容从 1 项增长到最多 4 项，超过后固定 4 项视口并可滚动；新提示在最上面，旧的往下排，位置以列表出现时第一条提示的触发元素为准，后续新增或更新不会改锚点。超出 4 项时列表接收滚轮，未超出时保持点击穿透。

- 音量 / 亮度：显示与下拉面板同款的一条等级条。音量只显示发生变化的那一路（输出或输入），亮度只显示最后变化的那块屏幕；同一路的连续变化更新同一个 OSD 条目并重新计时，只响应数值或静音状态的实际变化，初次读取不弹
- Wi-Fi / 蓝牙 / 互联：设备连接、断开和新出现在列表里的设备用文字提示；Wi-Fi 只提示连接状态，扫描到的新 AP 不弹。同类事件更新同一个 OSD 条目
- 电源：电池开始 / 停止充电时提示当前电量；新的 UPower 电池设备（耳机、鼠标、键盘等）或电源设备接入时提示类型和电量，交流电源只提示接入
- 通知：复用下拉列表的条目排版；每条通知是独立的 OSD 条目，同一条通知更新时替换对应条目并移到最上面，关闭或移除的通知会去掉自己的条目
- 剪贴板：只在新复制进历史时提示，删除、清空和把历史条目放回剪贴板不弹
